# 抽籤頁「營業時間」篩選 — 設計規格

- 日期：2026-07-24
- 相關檔案：[lottery.html](../../../lottery.html)、[export_to_sheets.py](../../../export_to_sheets.py)、`data/output/stores_data.js`

## 目標

在抽籤頁側欄新增一個「營業時間」篩選分類，選項為：
`營業中 ｜ 早餐 ｜ 中餐 ｜ 下午茶 ｜ 晚餐 ｜ 消夜 ｜ 未知`

以 **Google Maps 的真實營業時間**為判斷基準：
- 「營業中」= 依系統時間，店家此刻正在營業。
- 五個用餐時段 = 依系統時間的「今天」，店家營業時間與該時段時間窗有重疊。
- 「未知」= 抓不到營業時間的店家；**只有勾選「未知」時，這類店家才可能被抽到**。

## 已確認的決定

| 決定項 | 選擇 |
|---|---|
| 時段時間界線 | 預設方案（見下） |
| 打開頁面時的預設勾選 | **只勾「營業中」**（預設抽籤池＝現在有開的店） |
| 時段標籤依據哪一天 | 依「今天」（系統日期當天）的營業時間 |
| 元件型態 | checkbox 可複選，附「全選／全不選」，與「餐飲類型」一致 |

### 用餐時段時間窗（24 小時制）

| 時段 | 起 | 迄 |
|---|---|---|
| 早餐 | 05:00 | 10:30 |
| 中餐 | 10:30 | 14:00 |
| 下午茶 | 14:00 | 17:00 |
| 晚餐 | 17:00 | 21:00 |
| 消夜 | 21:00 | 次日 05:00 |

界線完整覆蓋 24 小時、無縫隙，因此「今天有營業」必然落在某個時段內。

## 資料模型變更

在 `stores_data.js` 每筆店家記錄新增一個 `hours` 欄位，供前端即時計算「營業中」與各時段。

- `hours: null` → 無營業時間資料（判定為「未知」）。
- `hours: Array<{d, o, c}>` → 每週營業時段。
  - `d`：營業起始星期，0=星期日 … 6=星期六（沿用 Google `periods` 定義）。
  - `o` / `c`：開店／關店時間，字串 `"HHMM"`（`"0000"`–`"2400"`）。
  - 一天有午、晚兩班 → 該日出現兩筆。
  - 跨午夜（例：18:00–02:00）→ 一筆 `{d:5,o:"1800",c:"0200"}`，前端以「`c` 數值 ≤ `o`」判定跨到隔天。
  - 24 小時營業 → 正規化為 7 筆 `{d:i,o:"0000",c:"2400"}`（i=0..6），讓前端邏輯統一、免特例。

> 精確的位元編碼（尤其 24h 與剛好午夜關店 `"0000"` 的判別）在實作階段以單元測試釘死；本規格只固定「欄位語意與代表性格式」。

範例：
```js
{
  "title": "某牛肉麵",
  // ...既有欄位...
  "hours": [
    {"d":1,"o":"1100","c":"1430"},
    {"d":1,"o":"1700","c":"2100"},
    {"d":2,"o":"1100","c":"1430"}
    // 週三公休則週三無任何筆
  ]
}
```

## 資料管線變更（export_to_sheets.py）

### 1. Place Details 加抓營業時間

擴充 `lookup_address_from_cid`（或新增 `lookup_place_details_from_cid`），把 `fields` 從 `formatted_address,name` 改為 `formatted_address,name,opening_hours`，一次取回地址與 `result.opening_hours.periods`、`weekday_text`。回傳結構同時帶回地址與正規化後的 `hours`。

### 2. 對所有有 CID 的店家抓營業時間並快取

- 目前只對「缺地址」的店家做 CID 查詢；需新增一輪：對**所有** URL 內含 CID 的店家（739/786，約 94%）確保取得 `hours`。
- 新增快取鍵 `__cid_hours__{cid_hex}`，與既有 `__cid_addr__` 快取並存，重跑不重複計費。
- 無 CID 的店家（47 筆，`url` 為空）→ 直接 `hours = null`（未知），不另做 Find Place 查詢。

### 3. 降級行為

- 未設定 `MAPS_API_KEY` 或 Places API 未啟用 → 靜默跳過，所有 `hours = null`（全部未知）。與現有「Places API 不可用時改由 Gemini 補地址」的降級策略一致。
- `opening_hours` 屬 Places API 的 Contact Data 計費層；靠快取避免重跑重複計費。

### 4. 輸出

- `stores_data.js`（`js_data`，約第 841 行）：每筆新增 `hours`。
- `output_stores.csv`（約第 822 行）：新增一欄「營業時間」，值用 Google `weekday_text` 以「 / 」串接，方便人工在 Sheet／CSV 核對；抓不到則留「未知」。此欄僅供人看，不參與前端計算。

## 前端變更（lottery.html）

### 1. 篩選 UI

在側欄新增「營業時間」`filter-section`（checkbox group，含「全選／全不選」），選項與 `value`：
`營業中(open-now) ｜ 早餐(breakfast) ｜ 中餐(lunch) ｜ 下午茶(tea) ｜ 晚餐(dinner) ｜ 消夜(latenight) ｜ 未知(unknown)`

**預設勾選狀態：只有「營業中」勾選，其餘全部不勾。**

### 2. 常數

```js
const MEAL_WINDOWS = {           // 分鐘（自午夜 0 起算）
  breakfast: [300, 630],         // 05:00–10:30
  lunch:     [630, 840],         // 10:30–14:00
  tea:       [840, 1020],        // 14:00–17:00
  dinner:    [1020, 1260],       // 17:00–21:00
  latenight: [1260, 1740],       // 21:00–次日05:00（跨午夜，>1440 表示到隔天）
};
```

### 3. 判斷邏輯（純函式，吃 `hours` + 傳入的「現在」時間）

抽成可測試的純函式，避免直接依賴 `new Date()`：

- `expandIntervals(hours)`：把每週 `periods` 展開成一週分鐘軸（0..10080，星期日 00:00 為 0）上的營業區間集合，處理跨午夜與週界（六→日）環繞。
- `isOpenNow(hours, now)`：`now` 換算成該週分鐘座標，落在任一營業區間即為 true。
- `servesMeal(hours, now, mealKey)`：以「今天」（`now` 當天 00:00 為錨）建構該餐時間窗的絕對區間（消夜延伸到隔天 05:00），與店家營業區間有重疊即 true。
- `hours == null` 時，`isOpenNow` / `servesMeal` 一律 false（無資料只能靠「未知」進池）。

### 4. 併入 updateFilters()

新增一段「營業時間」判定，與其他篩選群組一樣**群組間 AND、群組內 OR**：
- 勾「未知」→ `hours == null` 的店家通過。
- 勾任一時段 → 該店今天該時段有營業則通過。
- 勾「營業中」→ 該店此刻營業則通過。
- 任一勾選項命中即通過此群組；一項都沒勾 → 此群組不通過任何店（與其他群組行為一致）。

### 5. 與現有 fallback 的互動

現有「符合數為 0 → 從全部隨機抽並顯示『零符合』警示標籤」邏輯保留。因此預設只勾「營業中」時，即使凌晨可抽池很小或為 0，仍會退回全部抽出，不會卡住。

### 6. 中獎卡片（result-card）

中獎店家卡片加一個營業狀態標籤：`營業中`（綠）／`已打烊`（灰）／`營業時間未知`（灰），依 `isOpenNow` 與 `hours` 呈現。（今日詳細時段字串為選配，可放 details 列。）

## 邊界情況

- **跨午夜**：如 18:00–02:00，於凌晨 01:00 判為營業中（昨日時段延伸）。
- **24 小時**：正規化 7 筆全日，恆為營業中、命中所有時段。
- **今日公休**：該店有 `hours` 但今天無任何營業區間。它不符任何時段、也非營業中；且因為有資料，不算「未知」。結論：透過「營業時間」群組，這類店今天不會被抽到（符合「今天沒開就別抽」的預期）。
- **`hours == null`**：僅「未知」勾選時可被抽到。
- **凌晨勾「消夜」的已知取捨**：時段窗以「當前時鐘日」為錨，故凌晨 02:00 勾「消夜」指的是「今晚 21:00 起」的窗，而非此刻。此為刻意簡化；想抽「現在有開」請用「營業中」。文件記錄為已知限制。
- **無 URL 店家（47 筆）**：`hours = null` → 未知。

## 測試

- 純函式（`expandIntervals`／`isOpenNow`／`servesMeal`）以單元測試涵蓋：一般午晚兩班、跨午夜、24h、今日公休、`null`、週界環繞、各時段邊界時刻。
- 以 Playwright 對實際 `lottery.html` 做一次冒煙驗證：預設只勾「營業中」時計數合理、勾「未知」後含無資料店家、切換時段計數變動。

## 部署注意

- 重跑 `export_to_sheets.py` 重新產生 `data/output/stores_data.js`（含新 `hours`）。
- 依專案慣例，`stores_data.js` 被 `.gitignore` 忽略，部署到 gh-pages 時需 `git add -f`（force-add）。

## 範圍外（YAGNI）

- 不抓 `current_opening_hours`（含臨時／假日特例）；只用 `opening_hours`（常態週時段）。
- 無 CID 店家不另做 Find Place 補營業時間。
- 不做節假日／特休判斷。
- 時段時間窗暫不開放使用者在 UI 自訂（寫死常數，日後需要再議）。
