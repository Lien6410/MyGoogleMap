# 抽籤頁：來源清單篩選 + 候選名單展開/收納 設計

- 日期：2026-08-11
- 範圍：純前端——`lottery.html`、`lottery_logic.js`、`lottery_logic.test.js`。不動 Python 管線、不動 `window.STORES_DATA` 欄位契約、不動 `hours_logic.js`。
- 相關記憶：[[lottery-ui]]、[[project-mygooglemap]]、[[gh-pages-deploy]]

## 1. 背景

抽籤池自 2026-08-10 起限定為四個清單（想去的地點／回訪／常用早餐／常用晚餐，見 `mygmap/export.py` 的 `POOL_LISTS`）。前端有兩個缺口：

1. **看不到池裡有誰。** 只有一個「符合目前篩選條件的店家數量：N」的計數，調完條件無從確認調得對不對。
2. **無法單獨鎖定某個清單。** 現有「回訪狀態」是三選一 radio（全部／曾去過／未去過），只能區分去過與否，沒辦法「今天只從常用早餐抽」。

## 2. 目標 / 非目標

**目標**
1. 候選名單可展開/收納，隨篩選條件即時同步。
2. 能單獨鎖定任一來源清單來抽或來看。
3. 保留「曾去過／未去過」這兩個常用的複合選法。

**非目標**
- 不改資料契約、不改加權與抽籤機制、不動營業時間邏輯。
- 不持久化使用者偏好（重整回預設，沿用現有設計）。
- 不做虛擬捲動（池上限 449 列，純 DOM 足夠）。

## 3. 來源清單篩選（取代回訪狀態）

進階面板的三選一 radio 換成四個勾選框，比照現有「縣市」群組的樣式：

```
來源清單      全選 | 全不選 | 曾去過 | 未去過
─────────────────────────────────────────
 ☑ 想去的地點 (291)          只抽這個
 ☑ 回訪 (91)                 只抽這個
 ☑ 常用早餐 (15)             只抽這個
 ☑ 常用晚餐 (53)             只抽這個
```

- 括號內家數由目前的 `STORES_DATA` 現算，不寫死。
- 「只抽這個」＝ solo，等於取消其他三個。
- 「曾去過」＝勾 回訪＋常用早餐＋常用晚餐；「未去過」＝只勾 想去的地點。
- **複合選項只是幫忙勾勾選框的快捷，不是另一個篩選維度。** 篩選狀態始終只有「哪幾個清單被勾」一個維度，因此不可能出現兩個篩選器互相打架的空池。
- 全不勾時視同全勾，避免手滑清空造成無解空池。
- 「未去過」與「想去的地點 → 只抽這個」等價，仍兩者都留：前者語意上好找。

**為什麼取代而非並存**：四個清單的勾選是回訪狀態的嚴格超集（全勾＝全部、勾三個已去過的＝曾去過、只勾想去的地點＝未去過）。兩者並存並以 AND 組合會產生「未去過＋常用晚餐」這種必然為空、且看不出原因的組合。

**邏輯改動**：`storeMatches` 移除 `filters.visit` 分支，改為把 `store.source_list` 以 `, ` 切開，任一個在 `filters.lists` 裡即通過。`resolvePreset` 的回傳結構由 `visit` 改為 `lists`（Set）；「沒去過」情境＝`lists` 只有想去的地點，其餘情境四個全給。`visited` 欄位保留，僅供結果卡徽章顯示。

## 4. 候選名單展開/收納

- 觸發：counter-card 右側切換鈕「▾ 展開名單 / ▴ 收起名單」，帶 `aria-expanded`。預設收合，展開狀態只存在記憶體。
- 每列：`店名 ｜ 距離 ｜ 均消 ｜ 營業狀態`。
- 排序：距離近→遠，距離未知排最後，同距離按店名。
- 點一列在新分頁開該店的 Google Maps（`rel="noopener"`），與結果卡的一鍵開啟一致。
- 容器 `max-height: 45vh; overflow-y: auto`。
- 0 家時隱藏切換鈕，維持現有的「無符合，將從全部抽」提示。
- 同步：`applyFilters()` 算完 `filteredStores` 後呼叫 `renderCandidateList()`；展開中即時重繪，收合中只更新鈕上的數字。

## 5. 邏輯與測試

`lottery_logic.js` 新增純函式：

- `sortCandidates(stores)` — 上述排序規則。
- `POOL_LISTS` 常數與 `storeLists(store)`（切 `source_list`），供 `storeMatches` 與 UI 計數共用。

DOM 渲染留在 `lottery.html`。`lottery_logic.test.js` 補：solo 只留一個清單、複合「曾去過」涵蓋三個清單、全不勾視同全勾、排序把未知距離排最後。既有 20 個測試中與 `filters.visit` 相關者一併改寫為 `filters.lists`。

## 6. 驗證

- `node --test lottery_logic.test.js hours_logic.test.js` 全綠。
- 以實際的 `data/output/stores_data.js`（449 家）在瀏覽器手動確認：四個清單家數與 DB 產出的分佈一致（想去的地點 291／回訪 91／常用早餐 15／常用晚餐 53）、solo 後計數與展開名單筆數相符。
